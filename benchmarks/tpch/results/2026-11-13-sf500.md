# SF500 历史实验记录（2026-11-13）

这是迁仓前已完成实验的脱敏摘要，不是当前 benchmark 入口的新运行记录。数据来自原工作区保存的比较报告和逐查询结果；原始文件 SHA-256 保存在配套 JSON 中。原始机器目录、IP、证书及大体积行结果未发布。

## 实验条件

- 同一台 Linux 主机：64 个逻辑 CPU、503 GiB RAM、单 NUMA、两张 48 GiB RTX 5880 Ada。
- 输入复用同一不可变版本的 154 个 Parquet 文件，共 229,908,148,390 字节；22 次缓存命中，上传 0 字节。
- 基线：单 GPU，40 GiB 显存池、128 GiB 主机内存池、2 个扫描线程。
- 调整后：双 GPU，每卡 46 GiB 显存池、单 NUMA 416 GiB 主机内存池、64 个扫描线程，并启用统计缓存优化。
- 均通过 seekdb MySQL 查询路径，无 pin，不修改 Sirius 和桥接库。

## 结果与解释

Q1–Q22 全部与此前同一快照已验证的 CPU 参考结果一致。客户端查询耗时合计从 3122.206 秒降至 782.043 秒，约 3.99 倍。**这是两套 GPU 路径配置及统计处理实现之间的比较，不是 CPU/GPU 加速比，也不是单独某一代码优化的收益。**

计时包含 execute + fetchall，不包含首次 Parquet 准备、首次统计收集和外部结果比较；未清操作系统页缓存。单次顺序运行，没有多轮中位数。本轮未重新运行 CPU 套件，使用保存的精确参考值；Q11 规范化等值行顺序。仅四条原补测查询额外与保存的 CPU MySQL 元数据比较，其余查询通过服务预期 Arrow 类型检查并保存本轮元数据。因此不应把这份历史报告表述为本轮全部查询重新做了 CPU/GPU 元数据验收。

## 独立准备实验

同日另一阶段按主键范围、最多 8 个原生 SQL 连接、同一个 SCN 预导出完整八表：SQL 导出合计 680.36 秒，含调度和文件校验的全库准备为 865.94 秒，输出共 4,330,028,272 行。此过程不包含原始数据导入或跨机器传输，是显式预导出后发布快照的流程，不能当作自动冷查询准备时间。

最初单 GPU 的完整正确性验收曾因 CPU 超时补测 Q3/Q9/Q17/Q18，并调整 CPU DOP 和内存预算，因此那一轮 CPU 总计也不能用于严格的 CPU/GPU 性能比。
