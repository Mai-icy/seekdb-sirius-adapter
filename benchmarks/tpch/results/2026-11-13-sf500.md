# Historical SF500 experiments (2026-11-13)

This is a sanitized summary of experiments completed before the repository extraction, not a new run of the current benchmark entry point. Data comes from the comparison report and per-query results retained in the original worktree; the accompanying JSON records SHA-256 hashes of the source files. Original machine paths, IP addresses, certificates and large row result sets are not published.

## Experimental setup

- One Linux host: 64 logical CPUs, 503 GiB RAM, one NUMA node and two 48 GiB RTX 5880 Ada GPUs.
- Both runs reused the same immutable version: 154 Parquet files totaling 229,908,148,390 bytes; 22 cache hits and 0 uploaded bytes.
- Baseline: one GPU, a 40 GiB GPU memory pool, a 128 GiB host memory pool and 2 scan threads.
- Updated configuration: two GPUs, a 46 GiB pool per GPU, a 416 GiB host memory pool on one NUMA node, 64 scan threads and statistics cache optimizations.
- Both used seekdb's MySQL query path without pinning or changes to Sirius and the bridge library.

## Results and interpretation

All Q1–Q22 matched previously validated CPU reference results from the same snapshot. Total client query time decreased from 3122.206 seconds to 782.043 seconds, approximately 3.99 times faster. **This compares two GPU-path configurations and statistics-processing implementations. It is not a CPU/GPU speedup or the isolated effect of a single code optimization.**

Timings include execute + fetchall and exclude initial Parquet preparation, initial statistics collection and external result comparison. The OS page cache was not cleared. This was one sequential run, not a median over repeated rounds. The CPU suite was not rerun; comparisons used saved exact reference values, with Q11 tie ordering normalized. Only the four previously retried queries additionally compared against saved CPU MySQL metadata. The remaining queries passed the service's expected Arrow type checks and saved their current metadata. This historical report therefore does not establish a fresh CPU/GPU metadata comparison for every query in this run.

## Separate preparation experiment

In another phase on the same day, all eight tables were pre-exported using primary-key ranges, at most 8 native SQL connections and a shared SCN. SQL export totaled 680.36 seconds; full database preparation, including scheduling and file validation, took 865.94 seconds and produced 4,330,028,272 rows. This excluded initial data loading and cross-machine transfer. It used explicit pre-export followed by snapshot publication and must not be presented as automatic cold-query preparation time.

The original single-GPU correctness run retried Q3/Q9/Q17/Q18 after CPU timeouts and adjusted CPU DOP and memory budgets. Its CPU total is therefore also unsuitable for a strict CPU/GPU performance ratio.

The [machine-readable summary](2026-11-13-sf500.json) is for historical reference, not a repeated-run directory accepted by `summarize.py`. New comparisons should use the current runner and retain all raw samples, failures and actual deployment versions.
